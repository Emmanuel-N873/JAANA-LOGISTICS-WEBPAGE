BEFORE THE FILES

The big picture

PartThink of it as...Its real job
FrontendThe shop frontShows pages and reacts to clicks in the browser.
BackendThe staff roomChecks requests, permissions and prices before reading or changing records.
DatabaseThe order notebookKeeps bookings, staff access, prices and action records in Cloudflare D1.
GeoapifyA map helperFinds addresses and driving distance. Its private key belongs on the server.
Cloudflare PagesThe building on the internetHosts public files and runs API Functions.
TestsA practice playgroundTry sample actions to catch mistakes before real customers use the site.

The main folders

index.html / calculator.html → customer pages assets/ → customer styles, behaviour and pictures Jaana Backend/dashboard/ → staff screens and ticket source Jaana Backend/functions/api/ → backend request handlers Jaana Backend/server/ → shared server helpers Jaana Backend/migrations/ → database setup history Jaana Backend/tests/ → automated checks Jaana Backend/scripts/ → development tools docs/ → guides and design notes

Staff screens live inside the backend folder, but their HTML, CSS and JavaScript are still frontend code. Folder names alone do not tell you where code runs.

Follow one booking

1. Enter the shop. index.html shows the homepage. Book a Delivery opens calculator.html.
2. Pick addresses. calculator.js asks locations.js for suggestions. location-token.js gives an accepted address a signed, time-limited pass.
3. Ask for a price. estimate.js checks the passes and asks Geoapify for distance. pricing.js and weight-pricing.js calculate charges on the server.
4. Carry the details. For an eligible quote, the calculator saves a temporary shipment draft. booking-transfer.js brings it into the homepage booking form.
5. Save the order. booking.js submits details to bookings.js. The backend checks them, recalculates quoted pricing and saves a ten-digit reference. A matching retry returns the already saved booking.
6. Staff help the delivery. The dashboard uses protected APIs. Authorised staff update status; the backend records who did it.
7. Finish and print. After delivery, the ticket API supplies saved details. ticket.js displays saved charges and makes the barcode and tracking QR code.
Current weight rule: Up to 5 kg adds no surcharge. Over 5 kg through 20 kg adds 500 naira for each extra kilogram, rounding extra fractions upward. 5.5 kg adds 500 naira; 8 kg adds 1,500 naira. Above 20 kg uses the custom-quotation contact option. Historical saved prices are not recalculated.

Distance defaults are 300 naira per kilometre and a 2,000-naira minimum distance charge. Administrators can manage distance rates. The weight surcharge is added to the applicable distance charge.

FILE GUIDE 07

Customer and account API doors

Jaana Backend/functions/api/[[path]].js

What it does: Returns not-found responses for API paths that do not match a real endpoint.

Why it matters: Stops an unknown API address pretending to be a successful page.

Works with: Cloudflare Pages Functions routing

Jaana Backend/functions/api/bookings.js

What it does: Checks details, recalculates quoted prices, saves orders and returns a ten-digit reference. Matching retries reuse their saved booking.

Why it matters: Protects orders from invalid details, invented prices and duplicate submissions.

Works with: estimate.js, pricing.js, common.js and D1

Jaana Backend/functions/api/delivery-status.js

What it does: Looks up a reference and returns only public delivery status and update time.

Why it matters: Lets customers check progress without exposing names, phone numbers or addresses.

Works with: The Delivery Updates form and D1

Jaana Backend/functions/api/estimate.js

What it does: Checks selected-address tokens, asks Geoapify for driving distance and returns server-calculated charges.

Why it matters: Makes distance and price come from the backend rather than a customer-supplied total.

Works with: location-token.js, pricing.js and Geoapify

Jaana Backend/functions/api/locations.js

What it does: Finds Nigerian address suggestions with Lagos context, or turns device coordinates into an address. It validates results and signs accepted locations.

Why it matters: Helps customers choose useful addresses while limiting expensive provider requests.

Works with: Geoapify, location-token.js and calculator.js

Jaana Backend/functions/api/mfa.js

What it does: Handles authenticator enrolment, confirmation, disabling and recovery codes for the signed-in staff member.

Why it matters: Adds a second sign-in check and controlled recovery options.

Works with: server/mfa.js and dashboard MFA controls

Jaana Backend/functions/api/pricing.js

What it does: Reads distance rates, restricts editing to administrators and combines distance pricing with the shared weight calculation.

Why it matters: Keeps total-price calculation in one authoritative backend location.

Works with: weight-pricing.js, the pricing table and estimate/booking APIs

Jaana Backend/functions/api/staff.js

What it does: Handles staff sign-in, sign-out, current identity and password changes, including setup checks.

Why it matters: Keeps staff features behind an individual account and session.

Works with: staff-auth.js, mfa.js and staff tables

Works with: pricing.js, estimate.js and bookings.js

FILES YOU MAY ALSO SEE

Local, private and generated files

Some files exist only on one computer. Others are created again automatically.

Jaana Backend/.dev.vars

What it does: Supplies local backend settings and private keys.

Why it matters: Lets map and security features run locally without putting real keys into public code. Its values are not in this guide. Production secrets are configured separately in Cloudflare.

Jaana Backend/dist/

What it does: Holds public copies made by the build script: customer pages, admin.html, ticket.html and linked assets.

Why it matters: This is the static output published to Pages; Wrangler bundles Functions alongside it. Edit source files instead. Building can delete and recreate this folder. Its barcode/QR library copies come from node_modules.

Jaana Backend/node_modules/

What it does: Holds npm-installed tools: Wrangler for Cloudflare, Prettier for formatting, JsBarcode for barcodes, qrcode-generator for QR codes, and their helper packages.

Why it matters: Supplies reusable blocks. Thousands of internal package files are not individually authored JAANA source. Do not hand-edit them; package-lock.json records their selected versions.

Jaana Backend/.wrangler/ and local SQLite files

What they do: Store local runtime state, caches and development databases when tools create them.

Why they matter: Let you practise locally. They are not the production database and should not be published as application source.

.git/

What it does: Holds Git history, branches and version-control records.

Why it matters: Lets developers compare changes and recover earlier work. Use Git commands rather than editing its internals.

.agents/ and skills-lock.json

What they do: Hold local assistant skills and a record of installed skills, including project research, frontend, backend and deployment guidance.

Why they matter: Help the assistant follow a workflow. They are development helpers, not code customers run; their internal instruction/reference files are grouped here.

Private setup SQL, backups and logs

Examples, if created: .staff-bootstrap.sql, .staff-recovery.sql, database backups and *.log files.

They support setup, recovery, troubleshooting or backups and may hold sensitive details. Keep them out of Git and public output. Applying setup or recovery SQL can change a database; generating it alone does not.

A root package-lock.json, if present

The real npm project is Jaana Backend, whose lockfile lists the application dependencies. Running npm in the wrong folder can create an unnecessary empty root lockfile without a matching package.json. Do not confuse the two. Run project npm commands inside Jaana Backend.

docs/JAANA-CODEBASE-BEGINNER-GUIDE.html and .pdf

The HTML is this guide's editable reading/printing source. The PDF is its shareable document version. They explain the app but do not run it. Created after the inventory, they are outside the 102-file count.

YOUR FIRST STEPS

A gentle learning route

  1. Read README.md. Find a heading you recognise in index.html.
  2. Open styles.css and see how a section gets its colour and spacing.
  3. Read script.js for a small click handler before tackling the calculator.
  4. Follow one estimate from calculator.js to estimate.js, then read weight-pricing.js.
  5. Follow the booking journey using the frontend and backend guides for details.
  6. Read a related test before changing a feature. Practise locally; ask an experienced adult before changing accounts or production.

Useful local commands

From the project root in Bash:

cd "Jaana Backend" npm install npm test npm run build npm run check:frontend npm run check:deployment

In PowerShell, you can use npm.cmd instead of npm. Before running the whole app locally, follow the README: local settings, database migrations and a local staff account need setup. Opening HTML directly does not start the API.

Small safe practice: Change one heading locally, check it, then undo it. Do not practise on real orders, secrets, authentication or a production database.

Words made simple

HTML

The page structure: headings, forms, links and sections. Like the shelves and rooms of a shop.

CSS

Appearance rules: colour, spacing, size and layout. Like decorating and arranging the shop.

JavaScript (.js)

Instructions that make things happen. Browser code handles screens; server code checks requests and records.

.mjs

Another JavaScript extension used here for Node development scripts and tests.

JSON / JSONC

A structured way to write settings or data. JSONC also allows comments.

Markdown (.md)

Plain writing with simple symbols for headings, lists and links. Used for instruction guides.

SVG / PNG / JPEG / ICO

Picture formats. SVG describes shapes; PNG and JPEG store pixels; ICO commonly holds tab icons.

API / endpoint

A specific backend door that accepts a request and sends a response, such as /api/bookings.

Request / response

A question sent to the app and its answer. GET usually reads; POST sends an action; PUT changes settings; PATCH updates part of a record.

Database / D1 / SQL

The saved notebook, Cloudflare's database service, and the language used to read or change its tables.

Migration

A numbered recipe for changing the notebook structure. Apply it in the intended order to the intended database.

Authentication / permission

First prove who you are; then check what you may do. Signing in does not make every staff member an administrator.

Cookie / session

A browser-held pass and the server record recognising a signed-in person. HttpOnly helps stop browser scripts reading the session cookie.

MFA

An extra sign-in check, usually an authenticator code, in addition to a password.

Hash / signature / encryption

Different tools: a hash makes a comparison fingerprint, a signature detects unauthorised changes, and encryption hides content until unlocked.

Idempotency

When a booking answer gets lost, retrying the same request returns the saved booking instead of creating another one.

sessionStorage / localStorage

Small browser storage areas. The app uses tab-lifetime booking drafts and longer-lived reference storage. Neither is the real order database.

Build / deployment

A build packs public files. Deployment publishes the app. Building alone does not change the live website.

Dependency / lockfile

A borrowed library, and the exact-version list helping another computer install the same collection.

Regression test

A repeatable check that helps catch an old feature breaking after a change. Passing tests do not prove every situation is safe.

You do not have to understand everything at once. Learn one small journey, make one small local change, and check it before moving on.
